Git: Rewrite Pushed Commit Messages — Amend, Rebase, Force-With-Lease (Dual-Remote)

Step-by-step to reword commits already pushed and replace one remote with git push --force-with-lease, with backup, verification and collaborator reset.

Rewrite commit messages already pushed & remove old commits from remote

Complete procedure for commit --amend / rebase -i + push --force-with-lease with dual-remote support. Copy-paste ready for GitHub, GitLab, Bitbucket.
⚠️ Destructive operation: This rewrites shared history. Old commits will be removed from the targeted remote and become unreachable. Anyone who already pulled the old history will need to git fetch && git reset --hard origin/<branch>. Never force-push to main / master without team agreement and a backup branch.

0 — Prerequisites & backup

Requirements

Clean working tree, fetch permission, force-push permission on target branch. If branch is protected, temporarily allow force push in GitHub: Settings → Branches.

Golden rule

Never rewrite history that others base work on without warning them. Prefer --force-with-lease over --force.

Backup + fetch
git fetch --all
git status  # must be clean — commit or stash pending changes
git branch backup-before-rewrite
git log --oneline --graph --all -10
Tip: Check remotes first if you have two remotes. See section 3.

1 — Diagnose what to rewrite

Inspect history & remotes
git remote -v
# origin   git@github.com:you/repo.git (fetch) (push)
# second   git@github.com:client/repo.git (fetch) (push)

git branch -vv                    # see which remote your branch tracks
git log --oneline origin/<branch>..HEAD  # commits not yet on origin
git log --oneline -10             # pick hashes you want to reword

2 — Choose your scenario

Scenario A — Only the last pushed commit

Fastest: amend the message in place.

bash
git commit --amend -m "feat: correct commit message"
git log --oneline -3  # verify new message

Scenario B — Last N commits (e.g. last 3)

Interactive rebase. Replace pick with reword (or r) for each commit to edit.

bash
git rebase -i HEAD~3

Editor opens:

rebase todo list — edit then save
pick a1b2c3 old message 1
reword d4e5f6 old message 2
reword 789abc old message 3
# save and close → Git opens a message editor for each 'reword' sequentially

Scenario C — Older commits / all commits of branch

Rebase onto the remote base or a specific hash.

bash
git rebase -i origin/main
# or
git rebase -i <hash>^   # ^ means parent of oldest commit to reword
Conflict? Fix files, then git add . && git rebase --continue. Abort anytime with git rebase --abort.

3 — Push to ONE remote only (dual-remote)

Local rebase changes only local history. The remote you push to determines what gets overwritten. The other remote stays untouched.

SAFE

Use --force-with-lease

Fails if someone else pushed since your fetch. Prevents accidental overwrite.

DANGEROUS

--force

Overwrites unconditionally. Use only if --force-with-lease was rejected and you are sure.

Target a single remote

bash — replace names with your output from git remote -v
git push --force-with-lease origin <branch-name>
# explicit refspec (same result):
git push --force-with-lease origin HEAD:<branch-name>

Examples

two remotes: origin = your fork, upstream = client
# overwrite ONLY origin, upstream keeps old history
git push --force-with-lease origin feature/my-branch

# overwrite ONLY second remote
git push --force-with-lease second feature/my-branch

# DO NOT do this if you want to target one only:
# git push --all --force   <-- pushes to every remote
Check config: git config --get-regexp push and git config --get-regexp remote — if remote.pushDefault or multiple push URLs are set, an unqualified git push may hit both remotes.

4 — Verify & cleanup

bash
git fetch origin
git log --oneline origin/<branch-name> -10
git log --oneline second/<branch-name> -10  # compare second remote if exists
git diff backup-before-rewrite --stat  # should show no code diff, only messages

If verified, delete backup:

bash
git branch -D backup-before-rewrite

5 — Recovery if something goes wrong

bash
git reflog  # find previous HEAD
git reset --hard backup-before-rewrite
git push --force-with-lease origin <branch-name>

# or abort ongoing rebase
git rebase --abort

Old commits on GitHub/GitLab remain dangling until GC but are no longer reachable from the branch — this satisfies "removed totally from remote". Direct URL by hash may still work for a few days/hours if cached.

6 — What collaborators must do

for teammates who already pulled old history
git fetch --all
git checkout <branch-name>
git reset --hard origin/<branch-name>

Do NOT use git pull (it will merge old + new history). Use reset --hard.

TL;DR Cheat Sheet

copy all
git fetch --all && git branch backup-before-rewrite
git rebase -i HEAD~3   # pick -> reword, edit messages
git push --force-with-lease origin <branch-name>   # targets ONE remote only
git fetch origin && git log --oneline origin/<branch-name> -5
